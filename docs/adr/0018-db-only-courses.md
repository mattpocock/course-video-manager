# Courses are DB-only; retire on-disk repo backing

Courses were originally backed by a local git repo on disk: sections and lessons were folders, structure was parsed from the tree, and Publish wrote sidecar files (`.transcript.md`, `.body.md`, `.meta.json`, `TODO.md`) and a `changelog.md` alongside the videos. We retired that backing entirely (#1207). Course structure now lives only in the database, section/lesson identity is carried by `title` (the `path`, `repo_path`, and `fs_status` columns were dropped), and the CVM CLI replaced the course-editing agent and its virtual filesystem as the day-to-day editing surface.

This collapses the ghost/real distinction: with no filesystem to be present-or-absent on, every lesson is a plain DB record, so the ghost lesson/section/course concepts and the Materialize/Dematerialize machinery are gone. Publish now derives all structure from the DB and its Dropbox output is exclusively `.mp4` files plus a single `course.json` (nodes identified by `title` + lineage `id`, videos located by content-addressed `hash`); the changelog survives only as an in-app preview on the publish screen. We chose this over keeping the git-repo mirror because the dual DB/disk source of truth required constant sync-validation and the on-disk affordances (git push, materialize) were redundant once the CLI existed. Old on-disk course repos are left inert with their git remotes intact — no user data was touched.
